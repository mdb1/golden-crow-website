02. NORMALIZATION AND RENDERABILITY

02.01 Treat nil/missing arrays as empty at the presentation boundary if the existing model permits them. Trim strings for blank detection. Preserve the original array order within each section. Omit all-empty items. Do not deduplicate service records or subitems: repeated content may be intentional and must retain a distinct view identity.

02.02 Use an existing stable item ID if available. Otherwise create a deterministic presentation identity from the section key, original source index and current service identity. Do not key rows by title, description or URL alone. Do not generate new UUIDs in body. Expansion and search state must survive recomputation and scrolling, including repeated identical titles. Reset page-local state only when the service identity changes or the sheet is genuinely reopened as a new presentation.

02.03 B01 renderable item: question OR answer is nonblank. A missing question with a present answer gets the generic fallback question. A question without an answer is displayed as static text without a misleading caret. An all-blank record is omitted.

02.04 B02 and B03 renderable item: title OR description is nonblank. If description exists without title, use the corresponding fallback item title. A title-only item remains compact with no fake body paragraph.

02.05 B04 renderable item: title is nonblank OR URL is valid. A valid URL without title uses pg.service.links.fallbackItemTitle. A title with invalid/missing URL stays a noninteractive resource row with pg.service.link.unavailable. An invalid URL with no usable title is omitted. Never display a raw malformed URL as prose.

02.06 B05 renderable banner: title OR description is nonblank OR URL is valid. A button label alone is not content. For a renderable banner, apply the fallback title if missing. Apply the fixed example description only if the URL is valid and the authored description is blank. Apply the fallback button title only for a valid action whose authored buttonTitle is blank. If URL is invalid, preserve any authored title/description but do not promise the user can open it; use a static unavailable line instead of an active button.

02.07 B06 renderable item: title OR description is nonblank OR image URL is syntactically acceptable. For a text-containing item with a missing/invalid/failed image, use the bundled book artwork. Do not create illustrated items from a completely empty object. For an image-only record, reserve the image stage during loading. If its only image fails permanently and there is no authored text, omit that item after failure; a generic decorative book alone would invent an otherwise absent segment. Recompute anchors if this removes the section.

02.08 B07 renderable item: title OR description OR at least one nonblank subitem. Trim blank subitems and preserve remaining order and duplicates. Missing title gets the generic technical heading only when another field makes the group renderable. A title with no description/subitems is a static header, not an empty accordion.

02.09 B08 renderable item: title OR description OR instructions. Use the generic requirement heading when title is absent but another field exists. Do not invent preparation, volume, container, delivery, storage, fasting, temperature, timing or collection instructions. Instructions-only records remain visible and fully readable.

02.10 B09 renderable action: websiteUrl is a syntactically valid absolute HTTPS URL with a host. A blank value omits the entire block. A nonblank but invalid value may render the fixed website title and pg.service.website.invalidDestination as static footer content; no outbound icon or clickable surface. Do not upgrade HTTP automatically, guess the host, insert https://, or use a previous service's URL.

02.11 A section exists only when it has a renderable item, or the explicitly permitted unavailable website state. Fixed subtitles, illustrations and headers do not make an absent section visible. Do not render zero-item counters, blank placeholders, dummy rows or authoring instructions for missing optional fields.

02.12 If every block is absent, show the regular toolbar, a centered text empty state using pg.service.empty.title and pg.service.empty.body, and the regular close action. Omit hero, shortcuts, anchors, guidance, model sections and example banner. This is a completed empty state, not a loading skeleton.

ATOMIC BANNER COMPONENT KIT
Version 1.0 — 1024 × 500 logical artboard — magenta source accent #FF00FF

WHAT THIS PACKAGE IS

This is a source component library with a demonstrative, editable web assembly.
It is not a flattened scene, a whole-phone image, or a branded campaign.
The 93 source SVG graphics contain no visible text, prices, company names or
company logos. Their PNG counterparts are transparent raster exports of the
same primitives. Captions on catalogue pages are outside the actual assets.

The included preview is a reusable vector reconstruction of the banner's
composition and layering, not a pixel-identical extraction of the generated
reference. Gradients provide dimensional shading, but the reference's exact
raster textures and generated letterforms are not reproduced. The typography
uses the available browser/system fonts; no font files are included.

The critical difference from the rejected deliverables is granularity:
a phone is a DOM group assembled from separate physical and interface parts.
A feature card is a blank surface plus a separate pattern, text and crown.
A floating tile is separate depth, face, specular layer and symbol.
A price panel contains no number. A pill contains no label or crown.

QUICK START

1. Extract the ZIP without changing the folder structure.
2. Open index.html to test the assembled example. It has a name field, a color
   picker, and width controls. No external image or font request is required.
3. Open catalog.html to inspect and obtain each separate SVG or PNG.
4. Open exploded.html to inspect the independent device sublayers.
5. Integrate individual assets using implementation/components.js, or use the
   optional implementation/banner.js assembly as a starting point.

1. THE SOURCE COLOR SYSTEM

All accent shapes use currentColor with a default of #FF00FF. This is pure
saturated magenta, not gray and not green. Source highlights are white with
alpha; shadows are black with alpha. White screen surfaces and dark physical
bezels intentionally remain neutral.

Use the SVG primitives for the most direct theming. Set currentColor at the
SVG root. That changes the accent while retaining its white/black shading.
Do not desaturate the whole asset. Do not use a global hue-rotation, multiply,
or color blend mode on all phone layers. Those change neutral surfaces too.

An external SVG loaded with an ordinary <img> cannot inherit the page's
currentColor into that SVG document. Use the supplied inline renderer,
inline the SVG safely, or recolor the PNG once before use.

Standalone primitive example:

  <div id="tile" style="position:relative;width:120px;height:120px"></div>
  <script src="implementation/asset-library.js"></script>
  <script src="implementation/components.js"></script>
  <script>
    const color = '#ff00ff';
    mountAtomicPart('#tile', 'tile-extrusion', {
      x: 0, y: 0, width: 120, height: 120, zIndex: 1, color
    });
    mountAtomicPart('#tile', 'tile-face', {
      x: 0, y: 0, width: 120, height: 120, zIndex: 2, color
    });
    mountAtomicPart('#tile', 'tile-specular', {
      x: 0, y: 0, width: 120, height: 120, zIndex: 3, color: '#ffffff'
    });
    mountAtomicPart('#tile', 'icon-heart-pulse', {
      x: 27, y: 27, width: 56, height: 56, zIndex: 4, color: '#ffffff'
    });
  </script>

The result is one assembled tile, but it remains four separately replaceable
components. Replace the symbol without regenerating the tile's material.

For PNGs, implementation/recolor-raster.js exports:

  const blob = await recolorMagentaPng('assets/png/orb-diffuse.png', '#247cf2');
  const url = URL.createObjectURL(blob);
  imageElement.src = url;

Revoke the object URL when the image is no longer needed. Remote images must
permit CORS pixel access. A local Blob/File or same-origin image is preferable.

The PNG recolorer uses the source magenta's color contribution, rather than
painting over every pixel. It preserves the original alpha and leaves neutral
pixels alone. Its source assumption is the kit's #FF00FF plus white/black
shading; do not apply it to arbitrary colored photographs.

Transparency outside an object is actual PNG alpha. Checkerboards appear only
on catalogue pages; they are not inside the files.

2. FIXED ASPECT RATIO — DO NOT RE-FLOW THE DESIGN

The logical banner is exactly 1024 × 500, or 256:125 / 2.048:1.
The earlier 1792 × 1024 blueprint was not the required proportion. Do not use it.

At a rendered width W:
  scale = W / 1024
  rendered height = 500 × scale
  rendered x = logical x × scale
  rendered y = logical y × scale

Keep one 1024 × 500 artboard and scale that entire artboard once. All text,
borders, glow extents, icons, shadows and rotations travel with it.

Do not scale the phones independently at responsive breakpoints. Do not use
space-between to redistribute the left-column blocks. Do not permit a mobile
media query to turn the banner into a tall card if the requested fixed ratio
must be retained. If a separate mobile design is needed, define a new layout
rather than silently changing this one.

The included renderer uses ResizeObserver on the host and sets one outer
transform: scale(hostWidth / 1024), with transform-origin: 0 0.
The host uses aspect-ratio: 256 / 125 and clips the artboard at its edges.

The positions below refer to logical pixels, before this outer scaling.

4. DEVICE PLACEMENT IN THE BANNER

All three devices reuse those local components.
Transforms use transform-origin: 0 0 and the following literal order:
  transform: rotate(angle) scale(localScale)

The local scale is applied within the rotation. Do not additionally rotate
the layer PNGs or SVGs inside the device group.

  rear-left    x468 y152 localScale .79 angle -10deg global z20
  rear-right   x813 y122 localScale .76 angle  10deg global z21
  front        x635 y45  localScale .91 angle   5deg global z30

For coordinate conversion inside a device:
  globalX = groupX + s × (localX × cos(a) - localY × sin(a))
  globalY = groupY + s × (localX × sin(a) + localY × cos(a))

Apply the banner's outer responsive scale after these transforms.

All device controls and UI stay in the device-local coordinate system. Do not
position screen cards directly against the global banner after rotating a phone.

8. LIVE CONTENT AND ARBITRARY COMPANY NAMES

The production graphics contain zero names. The demo defaults to 'Tu marca'.
companyName is the full supplied company name. companyDisplayName is an
optional explicitly supplied shorter display form. There is no automatic
abbreviation, uppercase conversion or truncation.

The main headline region has a fixed width and height. The renderer reduces
font size and permits wrapping within that region. The header on each phone
uses a separate smaller fit. Typical short and long names are tested in qa.json.
Unlimited text cannot remain equally large in a fixed box. For very long legal
names, supply an approved companyDisplayName rather than silently clipping or
inventing an abbreviation. Font availability affects text metrics.

brandLogoUrl can use an approved actual logo. The generic heart symbol is a
placeholder icon, not a claim to be any company's logo. The logo image is not
hue-shifted or redrawn. A user-supplied logo may introduce additional colors;
the source primitives remain monochromatic.

Use textContent when assigning user-provided strings. The supplied renderer
already does this. Do not interpolate arbitrary names into raw HTML.

10. VALIDATION AND IMPORTANT LIMITATIONS

Check the SVG and PNG source files, not the preview JPGs. Every production
file is one primitive. All source assets are text-free. The only saturated
source accent is magenta; black shadows and white highlights have explicit
roles and should not be replaced with flat gray placeholders.

Default source geometry is not cropped to its painted pixels. In particular,
all device layers must retain their shared canvas for registration.

The same complete layout should measure 1024×500 at full size and 512×250 at
half width. Transform the artboard once. Do not remeasure source coordinates
against a screenshot that contains white webpage margins.

SVG definition IDs need to be unique when multiple instances are inlined.
Both supplied renderers prefix gradient, clipping and filter IDs per instance.
Do not copy raw SVG snippets into one document without that prefix step.

No remote network requests, licensed font files, invented official logos,
whole-phone production images or rasterized company-name graphics are included.
A modern browser with SVG, Canvas 2D, ResizeObserver and aspect-ratio support
is assumed. PNG raster output is supplied for simpler image-only integration.
The SVG implementation is the primary editable source.

Always recolor from the original magenta PNG, not a previously recolored PNG. Cache the recolored result by source filename and target hex color.

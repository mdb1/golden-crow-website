Connected partners

Firestore project: mydnamap
Collection: connected-partners
Access: authenticated GOD MODE (isBootstrap) only, enforced in SDK routes and repository.

Each document has these lower camel case contact and link fields:
  companyName: required trimmed string (1–180 characters)
  firstName: required trimmed string (1–140 characters)
  lastName: required trimmed string (1–140 characters)
  phoneNumber: required trimmed string (1–50 characters)
  email: required valid email, trimmed and lowercased (max 254 characters)
  meetingDate: nullable ISO civil date YYYY-MM-DD, without timezone conversion
  notes: nullable trimmed string (max 10,000 characters); blank becomes null
  linkedOrganizationId: nullable feed_organizations document ID
  linkedAppId: nullable app_configs document ID
  linkedOrganizationSnapshot: server-owned nullable { id, name }
  linkedAppSnapshot: server-owned nullable { id, publisherId, publisherName, status }

The generated Firestore document ID is returned as id but is not stored in the document.
Links reference existing Discover organizations and their organization apps.
Selecting an app alone derives its organization ID. Selecting a mismatched
organization/app, a missing linked record, or an individual app is rejected.
Snapshots are captured from authoritative linked documents on each partner save;
clients cannot submit snapshots. Clearing links also clears their snapshots.
Old seven-field contact documents decode with null links and snapshots.
There is no identity synchronization, importing, or cascading deletion. Deleting
a partner deletes only its contact document. No contact records are seeded.
Firestore creates the collection when the first contact is saved.

Every partner response additionally contains linkedOrganization and linkedApp,
resolved from current linked documents. A missing or invalid linked record yields
null while its stored ID and historical snapshot remain available. Apps that no
longer belong to the linked organization also resolve to null. Responses never
use historical snapshots as proof of a current organization or app status.
List pages deduplicate direct linked-document reads within the current page;
they never scan all organizations or apps. GET responses are private, no-store.

Backoffice grouping uses current resolved links and app status: no organization,
organization without app, free app for active_for_testing, and contract for active
or other active_* statuses. Non-active apps and unavailable/mismatched links are
shown explicitly for review rather than labeled as free or under contract.

SDK API:
  GET /admin/connected-partners[?cursor=<last document ID>]
    Returns { items, nextCursor }, 20 records per page, ordered by document ID.
    Reads at most 21 records to establish whether another page exists.
  GET /admin/connected-partners/:partnerId -> { partner }
  GET /admin/connected-partners/link-options?kind=organization|app[&cursor=<ID>][&organizationId=<ID>]
    Returns { items, nextCursor }; each option has { id, name } and app options
    additionally have { publisherId, status }. Pages read at most 21 documents
    and return at most 20 choices ordered by document ID. App choices exclude
    individual apps. When organizationId is provided for apps, a single direct
    read of the canonical organization_<organizationId> config returns its app.
  POST /admin/connected-partners -> 201 { partner }
  PUT /admin/connected-partners/:partnerId -> { partner }
  POST /admin/connected-partners/delete with { ids: [...] } -> { deletedIds }
    Atomically deletes 1–500 selected document IDs; already absent IDs are safe to retry.
    The backoffice asks for confirmation before single or bulk deletion.

Create/edit bodies accept the seven contact fields and the two nullable link IDs.
Omitted meetingDate, notes, and link IDs become null. Unknown fields, including
snake_case aliases, snapshots, and resolved-link response fields, are rejected.
Missing detail/update records return 404.

Backoffice routes:
  /god-mode/partners
  /god-mode/partners/new
  /god-mode/partners/:partnerId/edit
